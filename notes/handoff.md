# pacworld handoff (2026-09-17)
1. **Goal**: playable neural world model of Ms. Pac-Man (DIAMOND-style pixel diffusion, 64x64, 4-frame context). Conventions are in `CLAUDE.md`; all hyperparameters in `configs/*.yaml`; every script takes `--seed`.
2. **Data**: 352 episodes / 201,736 steps in `data/agent/` (PPO agent + eps/sticky exploration, ALE v5 at frameskip 1 with manual skip 4 and max-pool over all 4 raw frames, maze crop 172x160, RAM saved). Alignment check passes; 35 val episodes frozen in `configs/val_episodes.json`.
3. **Trained** (checkpoints only on the pod, `/workspace/pacworld/checkpoints/`): Model 1 = 18.8M-param EDM diffusion UNet, 100k steps, `model1_ema.pt` (val denoise 0.0008, single-step 49 dB). Model 0 = 5.8M MSE UNet baseline, 20k steps, `model0.pt` (44.9 dB). wandb: `smulakala06-san-jose-state-university/pacworld`.
4. **Pod**: `ssh root@213.173.107.231 -p 11398 -i ~/.ssh/id_ed25519`, repo at `/workspace/pacworld` (synced by rsync, not cloned), venv `.venv`, RTX 4090. Local Mac has no CUDA; MPS only works outside the sandbox.
5. **Measured, rollouts** (10 longest val episodes x 3 seeds, start step 100): Model 1 keeps the maze for 60 s (wall IoU 0.96 vs 0.26 for Model 0 at 900 steps); Pac-Man error 1.8 / 13 / 19 px at 15 / 150 / 450 steps; action responsiveness 0.79 / 0.45 / 0.30; gated ghost count falls from 4.0 to ~1 by step 150.
6. **Measured, ghost fade**: teacher-forced rollouts hold ghost mass at 96-100% of ground truth, so rendering is fine and the autoregressive loop is at fault. 3 -> 10 Euler steps recovers ~20 points of mass; 20 adds nothing. Inference ctx noise (0.01-0.1) only delays the collapse ~50 steps. Red survives (92% at step 450), pink/cyan/orange do not (20-25%); max-pool colour blending is NOT the cause (red and orange are both blended, opposite outcomes).
7. **Measured, mechanism**: lost ghosts are parked in the pen. Model pen stays occupied for a median 222 steps (real max 91); 16/30 rollouts park 200+ steps (real 0/30); 23/26 long parking runs begin right after the model's own Pac-Man respawn. No pixel-level freeze exists (0/30); a Pac-Man motion stall occurs in 5/30 rollouts and does not explain the metrics.
8. **Detector caveats**: ghosts stacked in the pen blend to a colour no ghost class matches, so ghost count and ghost mass cannot see them; use pen occupancy. Flickering sprites appear as max(colour, background), e.g. red (200,72,136); these variants are in the palette. RAM map: Pac-Man x/y 10/16, direction 56&3, frightened 116, lives 123, ghost x 6-9 and y 12-15 (orange, cyan, pink, red), pen at (88,80).
9. **Open hypothesis A (leading)**: the post-respawn pen release runs on a timer that a 4-frame context cannot observe (real ready-pause is 19-39 steps). Test: longer context, or condition on steps-since-respawn; success = pen occupancy run lengths match ground truth in `pen_timer_analysis.py`.
10. **Open hypothesis B**: the model handles the first release correctly only because it starts from real context; check whether release timing after a teacher-forced respawn is also correct.
11. **Open hypothesis C**: residual loss at 10-20 sampler steps is exposure bias (never trained on own outputs); test by fine-tuning with rolled-out context. Responsiveness after ~5 s mostly measures trajectory agreement with ground truth, not control; it needs a model-world definition before it is trusted.
12. **Not done**: no model change has been made since the 100k run; nothing beyond level 1 / maze 1 is covered; eval horizons past 450 steps have no ground truth (episodes are 589-915 steps).
